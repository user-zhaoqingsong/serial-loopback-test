# 串口环回测试

[![Build](https://github.com/user-zhaoqingsong/serial-loopback-test/actions/workflows/build.yml/badge.svg)](https://github.com/user-zhaoqingsong/serial-loopback-test/actions/workflows/build.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

Windows 数据链路自动环回测试工具，支持串口、TCP Client、TCP Server、UDP，以及双端点中继环回和单端点全双工测试。

运行环境：Windows 10/11，.NET Framework 4.8。

[下载最新 Windows EXE](https://github.com/user-zhaoqingsong/serial-loopback-test/releases/latest)

## 功能

- 双端点环回：A 连续发送，B 校验并原样回传，A 再次校验。
- 单端点全双工：串口可通过 TX/RX 自环，TCP/UDP 可连接外部回显端。
- A/B 可分别选择串口、TCP Client、TCP Server 或 UDP；TCP/UDP 采用独立接收线程。
- RSLP v1 帧协议包含帧头、版本、数据模式、长度、序号、帧起始种子、头部 CRC32 和整帧 CRC32，接收错位或坏帧头后会自动搜索下一帧头恢复同步。
- 串口自动使用最多 3 帧在途，纯网络自动使用 32 帧；也可手动选择 1–32 帧。发送不等待单帧校验结果，错误和超时不会阻断后续收发。
- 20、40、60、80、100 字节固定帧长或逐帧随机长度。
- 递增、全 55、全 AA、55/AA 交替、自定义 HEX、PRBS7、PRBS15、PRBS31 或随机内容。
- PRBS 和随机内容使用可设置、可记录的种子，可以复现测试数据。
- 常用波特率选择，以及 300–3000000 范围内的自定义波特率。
- 实时统计 CRC 错误、丢帧、重复帧、乱序帧、错误字节、错误位数、在途帧和往返耗时。

## 接线

### 双串口环回

- A.TX → B.RX
- A.RX ← B.TX
- A.GND ↔ B.GND

### 单端口全双工自环

- UART/RS-232：端口 A 的 TX 与 RX 短接。
- RS-422 或四线制差分端口：A.TX+ → A.RX+，A.TX- → A.RX-。
- 根据设备要求连接参考 GND。端点 B 在此模式下不会打开。

## TCP/UDP 端点格式

- TCP Client：`主机:端口`，例如 `127.0.0.1:9001`。
- TCP Server：`本机监听地址:端口`，例如 `0.0.0.0:9001`。启动后等待客户端连接，连接前不会发送测试帧。
- UDP：`本地端口@远端主机:远端端口`，例如 `9000@127.0.0.1:9001`。

在同一程序中测试 TCP 时，可将 A 设为 `TCP Client 127.0.0.1:9001`、B 设为 `TCP Server 0.0.0.0:9001`。测试 UDP 时，可将 A 设为 `9000@127.0.0.1:9001`、B 设为 `9001@127.0.0.1:9000`。纯网络模式不使用波特率；TCP/UDP 为测试网络设计，不提供 TLS 或身份认证，请只在可信网络中使用。

## 使用方法

1. 打开 `dist/串口环回测试.exe`，选择“双端点环回”或“单端点全双工/自环”。
2. 为 A/B 选择串口、TCP Client、TCP Server 或 UDP，并填写对应端点。串口默认通信格式为 8N1、无流控。
3. 设置最低回传超时、预设内容、帧长和数据种子。串口波特率下拉框提供常用值，也可以直接输入 300–3000000 范围内的整数；最终是否支持由串口硬件及驱动决定。
4. 帧长可选择 20、40、60、80、100 字节；也可独立启用“内容随机”和“帧长随机”。
5. 点击“开始环回测试”。校验失败或帧超时只累计错误，程序仍持续填充在途窗口；端点断开等不可恢复错误才会停止。
6. 查看帧级正确/错误、CRC、丢帧、重复、乱序、错误字节/位和最近/平均环回耗时。

预设内容支持递增字节、全 55、全 AA、55/AA 交替、自定义 HEX 循环和 PRBS7/15/31。PRBS 多项式分别为 x⁷+x⁶+1、x¹⁵+x¹⁴+1、x³¹+x²⁸+1；种子 0 会规范化为 1，非零种子可复现同一字节序列。自定义 HEX 支持空格、连续字符、逗号、短横线和 `0x` 前缀。种子在启动日志中以十六进制记录，运行日志可随时清空。

界面中的帧长是载荷长度。RSLP v1 每帧额外增加 20 字节头部和 4 字节 CRC 尾部；例如 100 字节载荷在线路上占 124 字节。CRC32 使用 IEEE 多项式，头部 CRC 用于安全恢复帧边界，整帧 CRC 用于检测头部和载荷损坏。

程序会根据波特率和帧长度估算完整往返所需时间。在 9600/19200 等低波特率下，实际超时会自动增加，界面输入值只作为最低阈值；启动日志会显示本轮采用的实际超时时间。

### 在途窗口与硬件实测

串口“自动”窗口采用 3 帧，这是在 Windows + 双通道 CH347、100 字节 PRBS31 载荷、COM7/COM8 交叉环回上测得的长期稳定值。窗口增大可以提高吞吐，但 USB 串口桥的双向 FIFO/USB 批次可能溢出；损坏帧无法形成有效序号回包时，最终会表现为“超时/丢帧”，并不表示实际硬件延时达到了超时阈值。手动选择大于 3 帧时，程序会在日志中提示风险。

该硬件的单帧往返实测如下（RSLP 线路帧共 124 字节）：

| 波特率 | 平均 RTT | 波特率 | 平均 RTT |
| ---: | ---: | ---: | ---: |
| 4800 | 527.36 ms | 230400 | 12.89 ms |
| 9600 | 264.20 ms | 460800 | 7.00 ms |
| 19200 | 133.96 ms | 921600 | 4.10 ms |
| 38400 | 68.29 ms | 1000000 | 3.70 ms |
| 57600 | 45.71 ms | 1500000 | 2.80 ms |
| 115200 | 23.68 ms | 2000000 | 2.40 ms |

3 帧窗口下，2M/100 字节连续 30 秒完成 18033 帧，115200/100 字节连续 30 秒完成 1344 帧，两次测试均为 0 CRC、0 丢帧、0 错误字节。该结果只代表上述实测硬件；其他 USB 串口桥可使用“在途窗口”手动调优。

## 构建

在 Windows PowerShell 中运行 `build.ps1`。脚本使用系统自带的 .NET Framework 4.x 编译器，执行核心逻辑测试后在 `dist` 目录生成单个 EXE。

GitHub Actions 会在每次推送和 Pull Request 时使用 Windows runner 执行相同的构建与测试，并上传 EXE 构建产物。
